# 饮片炮制记录台

一条记录是一整包炮制文书，里面是工序数组，不是拆成多列指标的普通表单。清炒温度和时长不在范围内就不能放行。

## 季节温区日历

炮制员为十二个月各存一份清炒温度上下限（默认 80~150）。写入批次必须声明月份，缺月拒写；服务端按该月当前温区判定放行。改某月温区会向季节流水追加一行，早先流水行不被改写，新线只约束改线之后递交的批次，旧记录判定不回改。质检员只读各月温区与流水。

顶栏挂「季节温区」链，落地页含十二月温区表、改线区（仅炮制员）、季节流水。

## 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/season-zones | 十二月当前温区（登录即可读） |
| GET | /api/season-ledger | 季节流水，新的在前（登录即可读） |
| POST | /api/season-zones | 改某月温区，追加流水（仅炮制员） |
| POST | /api/batches | 写批次，body 必须带 `month`（1~12） |

## 启动

```bash
cd projects/14-herb-process-record

```

## 验收

1. processor 登录后，甘草为放行，黄芩为未放行（温度过低）。
2. 再写一条温度 200 的清炒（须声明月份），结论仍是未放行。
3. checker 看不到写入按钮，也看不到改线表单，只能读温区表与流水。
4. 把 3 月温区抬到 100~150：声明 3 月递交 90℃/12分钟 → 未放行；声明 4 月（仍 80~150）同样 90℃/12分钟 → 放行；不声明月份 → 拒写。
5. 季节流水多一行 3 月 100~150，早先 12 行原样保留。
